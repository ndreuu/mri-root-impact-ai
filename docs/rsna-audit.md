# S001 — аудит моделей стенозов RSNA

Проверено 19 октября 2026 года. **Обученные RSNA-веса найдены; аудит завершен, inference стенозов еще не выполнялся.** Для следующей проверки выбран небольшой опубликованный side-classifier `0203` решения Moyasii / tkmn с MIT-кодом и MIT-набором весов. Это кандидат для исследовательского запуска, не воспроизведение полного призового ансамбля. Компактный вариант Adam Narai точнее соответствует раздельным входам исходного плана, но его условия использования весов пока не установлены.

Версии, размеры, SHA исходников, запросы метаданных и ограничения закреплены в [инвентаре](../harness/upstreams/rsna.json). Веса не загружались, внешний код не исполнялся, зависимости не устанавливались. S002 проверит сами файлы и окружение; S003 выполнит первый inference.

## Исходная задача и наши выходы

[RSNA](https://www.rsna.org/artificial-intelligence/ai-image-challenge/lumbar-spine-degenerative-classification-ai-challenge) оценивает три вида дегенеративных изменений. С учетом стороны это пять conditions на пяти дисковых уровнях L1/L2…L5/S1 — 25 сочетаний. В нашем текущем контракте боковым компонентам соответствуют 20 сочетаний:

| RSNA condition | Серия аннотации | Компонент C001 |
|---|---|---|
| Left / Right Neural Foraminal Narrowing | Sagittal T1 | `foraminal_stenosis`, отдельная сторона |
| Left / Right Subarticular Stenosis | Axial T2 | `subarticular_stenosis`, отдельная сторона |
| Spinal Canal Stenosis | Sagittal T2-like | Отдельного компонента пока нет |

Исходная шкала — **Normal/Mild, Moderate, Severe**. Первый класс объединяет норму и легкие изменения; его нельзя переименовывать в «патологии нет». Плоскость аннотации не определяет вход любого checkpoint: некоторые решения используют сразу все три серии. [Первичная публикация LumbarDISC](https://pubs.rsna.org/doi/full/10.1148/ryai.250480), [официальные приложения S1–S3, стр. 2–5 и 14 PDF](https://pubs.rsna.org/doi/suppl/10.1148/ryai.250480/suppl_file/ryai250480suppa1.pdf).

В протоколе RSNA L5/S1 соответствует самому каудальному полностью сформированному диску, включая случаи переходной анатомии. Задача соревнования не проверяет истинную анатомическую нумерацию. Совпадение с CSV не подтверждает номер корешка для fusion. Axial T2 мог покрывать минимум три уровня; отсутствие покрытия остальных не означает норму. CSV-координаты — центры областей оценки, не маски грыж и не разметка корешков.

## Кандидат для S002: опубликованный side `0203`

Источник — commit `8a3cd3e615bf24c934dc5440e96ee52aa68c1386`, [фактический inference](https://github.com/Moyasii/Kaggle-2024-RSNA-Pub/blob/8a3cd3e615bf24c934dc5440e96ee52aa68c1386/src/predict.py), [config](https://github.com/Moyasii/Kaggle-2024-RSNA-Pub/blob/8a3cd3e615bf24c934dc5440e96ee52aa68c1386/src/stage2/tkmn/config/0203.yaml). Checkpoint `stage2/tkmn/side/v9/0203/exp0203_fold1_best_score.pth`, **41 158 224 байта**, явно включен автором в опубликованный inference. Для v2 GET Range вернул 206 и общий размер 41 158 224; тело ответа не читалось, SHA-256 самого веса пока неизвестен.

Это `RSNA2024AttentionNet`: MnasNet Small, отдельный backbone для каждой из трех последовательностей, GeM и attention, два выхода NFN / SS по три класса. На каждый уровень и сторону нужны **15 SagT1 + 15 SagT2-like + 10 AxT2 crop-срезов, 224×224**. Порядок условий берется из `conditions=[neural_foraminal_narrowing, subarticular_stenosis]`, выходной class order в inference CSV — `normal_mild, moderate, severe`.

Нужны авторские keypoint-модели и построение ROI dataset v9: sagittal crop 35×50 мм со смещением −5 мм по высоте; axial 45×75 мм со смещением +5 мм. Затем выбирается сторона, справа axial crop отражается. Preprocessing включает преобразование DICOM в изображения, выбор/порядок срезов, resize и `A.Normalize(mean=0.5,std=0.5)`; весь путь до нормализации предстоит воспроизвести, отдельный Normalize сам по себе недостаточен. Классификатор требует **все три серии**. Его результат нельзя описывать как NFN исключительно из T1 и SS исключительно из AxT2; такой раздельный baseline остается отдельной конфигурацией.

Опубликован также ResNet18 `0123`, 160×160, checkpoint 140 646 108 байт. Выбор одного checkpoint вместо ансамбля — новая конфигурация; призовые метрики на нее не переносятся. У `0203` fold1 пока не установлено пересечение с нашим development case; у локализаторов оно проверяется отдельно.

`src/predict.py` жестко задает `cuda:0`, создает модели и выполняет pipeline на верхнем уровне. Импортировать файл в основной harness нельзя. Его inference class отличается от training class; отдельный CPU worker должен сохранить архитектуру и preprocessing, отключить сетевую инициализацию backbone перед загрузкой весов, проверить строгую совместимость state_dict. Прямой `run_quick.sh` скачивает также весь competition dataset и дополнительные данные — его не запускаем. CPU-скорость и совместимость нашего runtime еще не измерены.

## Компактная альтернатива: Adam Narai split

[Исходники моделей](https://github.com/adamnarai/kaggle-rsna-2024/tree/3a30fb41ec2af3cd1337d676686880fac9184e7c/rsna2024) и фактический notebook/API snapshot подтверждают ResNet18 + GRU, пять срезов, ROI 50×50 мм, 128×128. Class mapping в скачанных config: Normal/Mild=0, Moderate=1, Severe=2. NFN использует SagT1, SS — AxT2; один классификатор работает с обеими сторонами, правый axial отражается. Аргументы level/side не используются в forward: правильная привязка зависит от ROI.

| Назначение | Kaggle dataset v1 | Checkpoint cv1 |
|---|---|---:|
| NFN | `adamnarai/rsna-2024-hardy-voice-1244-5fold` | 57 381 984 байта |
| SS | `adamnarai/rsna-2024-fiery-meadow-1254-5fold` | 57 382 111 байт |

Три coordinate checkpoint для автоматической подготовки требуют еще 269 857 356 байт; один fold всего пути — 384 621 451 байт. У всех пяти наборов условия весов `Unknown`. Доставка двух classifier файлов проверена Range-запросами без чтения тела; Kaggle оборачивает эти файлы в ZIP. Точные URL, configs SHA и notebook snapshot SHA сохранены в inventory; SHA медицинских checkpoint пока `null`.

У notebook есть CPU fallback. Однако `get_roi` возвращает нули при отсутствии серии/координаты, возможны частично пустые crops; встречается fallback spacing 4.5 мм. Это нельзя переносить как обычный вход без статуса недостаточности. Фиксированные SagT1 смещения 14.9…18.9 мм от середины требуют проверки на наших сериях. Автоматическая AxT2 локализация дополнительно использует SagT2.

## Требования к нашему адаптеру

1. Закрепить код, отдельные weights, class/condition order, preprocessing, версии зависимостей и фактические SHA до исполнения. Успешная выдача HTTP не проверяет содержимое модели.
2. Сохранить source image/frame, IOP/IPP/spacing, все crop/resize/flip transforms и источники локализации. На нашем AxT2 шесть ориентаций; нельзя использовать один affine на все 30 кадров. Проверить формулы на анизотропном и наклонном синтетическом DICOM, а не только на квадратных пикселях контрольного случая.
3. Для каждого из 20 целевых сочетаний сформировать отдельный assessment с исходной RSNA-шкалой. Нет серии/модели → `not_run`; непокрытый уровень, неоднозначная сторона/номер или некорректный ROI → явно неопределенный результат. Нулевой fallback не подтверждает Normal/Mild. Native grade можно сохранить при `indeterminate`.
4. Зафиксировать выбор из нескольких серий и работу со стороной пациента. Отклонять неподдержанные ориентации; не исправлять их молча. Номера RSNA / SpineNet сохранять с происхождением, без автоматического подтверждения root numbering.
5. Автоматический inference не читает train grade/coordinate CSV. Если используем эталонные ROI для отдельного эксперимента, явно обозначить oracle-localization и не объявлять проверкой полного pipeline.
6. Проверить вероятности и их порядок; не трактовать confidence класса как вероятность радикулопатии. Центральный стеноз не записывать в боковые компоненты. Fusion и его пороги остаются F001.

## Контрольный случай и следующий шаг

Наш study `3139265320` находится в **train_images / train.csv**. Имеет 25 координат и все пять уровней/conditions; среди его меток нет Severe. Это development/sanity пример. До проверки исключенного fold нельзя считать его независимой оценкой выбранных весов; даже исключенный fold не делает один случай оценкой точности. Метки и снимки остаются вне Git. RSNA не дает эталона размера грыжи, пораженного корешка или клинической радикулопатии.

S002 получает выбранный небольшой licensed комплект и проверяет байты, provenance и CPU окружение. S003 запускает native модель с автоматическими ROI, сохраняет исходные оценки и C001 с неопределенностью. Наличие этой ветки не закрывает LDH D002. L003 независимо готовит source-frame geometry и сопоставление дисковых уровней.
