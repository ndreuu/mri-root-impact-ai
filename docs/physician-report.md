# F003 — отчет для врача и объяснение решения

Основной результат для чтения — `report.html`: локальный HTML на русском языке, который открывается в браузере без установки пакетов и доступа к сети. Тот же материал сохраняется в `report.md`. Структурированные результаты и проверочные сведения остаются в `fusion.json` и `run.json`.

## Как читать

Сначала приведены итог, охват оценки и ограничения. Затем — предварительные находки по пяти уровням, двум сторонам и двум зонам. Оценка модели отделена от вывода о корешке: неопределенная анатомическая привязка остается неопределенной, даже если модель вернула класс стеноза.

Для каждого сочетания уровня, стороны и зоны можно проследить четыре шага:

1. **Исходная находка.** Предварительный уровень, сторона, зона, класс стеноза и доступность исходной оценки.
2. **Условия интерпретации.** Статус источника, подтверждение нумерации и стороны, геометрия, межсерийное сопоставление, достаточность изображений, покрытие входных серий, пригодность вероятностей и согласованность оценок.
3. **Применимое правило.** Порог исследовательской версии и анатомическое соответствие. Названный корешок появляется в выводе только после прохождения всех предусмотренных проверок.
4. **Результат.** Потенциальное воздействие, отсутствие кандидата только по оцениваемому критерию либо недостаточность данных с конкретной причиной.

Общая анатомическая таблица приведена отдельно как справочная схема. Она не становится персональным выводом для строк, в которых привязка не подтверждена. Объединенный класс «Норма / легкий стеноз» не разделяется на два диагноза. Умеренный стеноз остается неопределенным для выбранного правила; выраженный формирует кандидата только при пригодных источниках и подтверждениях.

Вероятности относятся к классам стеноза модели. Они не обозначают вероятность воздействия на корешок или клиническую уверенность. Идентификаторы исходных оценок, изображения, версии моделей, исходные коды и SHA доступны в технических подробностях. Достоверность экспертного подтверждения не устанавливается одной проверкой формата файла.


Сохраненный F002 расположен в соседней папке `fusion/f002-001`; его файлы не переписываются. Новый отчет использует те же исходные MRI-результаты и неизменную policy 0.1.0. Изменение представления не подтверждает нумерацию, регистрацию или клинический диагноз.

## Запуск и проверка

Из корня локального репозитория:

```sh
MRI_CASE=/Users/andrew/Datasets/mri-root-impact-ai/rsna-3139265320

python3 scripts/fuse_mri.py \
  --study "$MRI_CASE/prepared/study.json" \
  --spinenet-run "$MRI_CASE/localization/l002-001" \
  --rsna-run "$MRI_CASE/stenosis/s003-001" \
  --crosscheck-run "$MRI_CASE/geometry/l003-001" \
  --output "$MRI_CASE/fusion/f003-001" \
  --verify-only
```

Для нового отчета удалить `--verify-only` и указать новую выходную папку. Команда выводит полный путь к HTML в поле `report`. Браузер позволяет распечатать отчет или сохранить его в PDF.

HTML, Markdown и JSON связаны SHA в `run.json`. Проверка повторно вычисляет все три результата; редактирование текста при сохранении исходного JSON выявляется даже после подмены SHA в metadata. Версия представления — `report_format_version=1.0`. Нейросети повторно не запускаются.

На контрольном исследовании все 20 оценок имеют подробный разбор и неопределенный итог. Два свежих запуска дали побайтно одинаковые HTML, Markdown и fusion JSON; JSON совпал с прежним F002. Проверены все 161 входной файл и 27 файлов кода; `--verify-only` не пишет файлы. Все 353 теста проходят в RSNA runtime; core Python 3.9 — 308 pass и 45 optional skips. Проверки представления охватывают неопределенность, условные положительные выводы, неполный охват корешка, непринятые шкалы, вероятности, экранирование и подмену текста.

Исторический F002 проверяется кодом коммита `0d61c27`, которым он создан: его отчет и набор артефактов предшествуют HTML-представлению. Новая команда проверяет новый F003. Смысл и формат `fusion.json` не менялись.
