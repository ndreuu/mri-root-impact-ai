# Отчет для врача: снимки, факты и анатомическое правило

Каждый успешный `scripts/fuse_mri.py` автоматически создает `report.html`, `report.md`, `report-evidence.json`, `fusion.json` и `run.json`. Основной результат для врача — HTML: снимки встроены в файл, доступ к сети не требуется. Markdown ссылается на проверенные локальные PNG.

## Как читать

1. **Что получено.** Сводка исходных степеней, без подмены находок формальным статусом достоверности. В контрольном случае: 4 умеренных стеноза слева на L3–L4 и L4–L5, 16 объединенных классов Normal/Mild, выраженных стенозов модель не выдала.
2. **Фораминальный стеноз.** Sagittal T1: по одному проверенному кадру с ROI и увеличением для каждого уровня и стороны — 10 оценок.
3. **Субартикулярный стеноз.** Axial T2: также 10 оценок с исходным кадром и увеличением ROI.
4. **Межпозвонковые диски.** Пять доступных Axial T2 кадров для осмотра. LDH-детектор не подключен: изображение не является автоматическим обнаружением грыжи, ее размера или стороны.
5. **Факты и fusion.** Предварительная степень и исходные level/side/zone → условное соответствие выходящему или проходящему корешку → интерпретация степени. Условное соответствие предполагает правильность native меток; оно не становится подтвержденным кандидатом.
6. **Достоверность итогового вывода.** Отдельно приведены подтвержденность нумерации, стороны, геометрии, совмещения серий, достаточность изображений и исходный статус. Все подробности можно раскрыть.

Фораминальный L4–L5 условно соответствует выходящему L4, субартикулярный L4–L5 — проходящему L5. Для L5–S1 явно используются L5/S1. Умеренная степень показывает анатомическую связь, но не выполняет выбранный исследовательский порог положительного вывода. Normal/Mild остается объединенным классом, а не заключением об отсутствии изменений.

В [Sung et al., 2017, таблица 2](https://www.kjronline.org/DOIx.php?id=10.3348/kjr.2017.18.1.249) рассматриваются контакт, смещение и компрессия. Шкала статьи 0–3 не приравнивается к классам RSNA. Пример «L4–L5 + левосторонняя грыжа + выраженный левосторонний субартикулярный стеноз → левый проходящий L5» показан отдельно как иллюстрация правила, а не находка контрольного исследования.

## Что именно изображено

Используются существующие, проверенные S003 source overlays. Для каждой оценки выбирается средний отсчет из **фактического упорядоченного набора входов модели**, с сохранением повторяющихся views. Это воспроизводимая иллюстрация одного входа, а не поиск самого выраженного стеноза или доказательство компрессии.

Рамка соответствует `source_crop_box` выбранного level/side/sequence; увеличение показывает ту же область на размеченном кадре. Рамка не является сегментацией грыжи, стеноза или корешка. Показана исходная ориентация; необходимость горизонтального переворота во входе модели указана отдельно. Source image/frame, ROI ID, индекс выборки, размеры и SHA сохраняются в `report-evidence.json`.

Выбранный RSNA classifier использует совокупность SagT1, SagT2 и AxT2. Показ отдельной последовательности для конкретной зоны не означает, что classifier оценивал ее изолированно. В режиме явных C001 inputs без frozen spatial/overlays иллюстрации обозначаются как непредоставленные; поддельные снимки не генерируются.

## Открыть или повторить

```sh
open /Users/andrew/Datasets/mri-root-impact-ai/rsna-3139265320/fusion/f004-001/report.html
```

Из корня репозитория:

```sh
MRI_CASE=/Users/andrew/Datasets/mri-root-impact-ai/rsna-3139265320
python3 scripts/fuse_mri.py \
  --study "$MRI_CASE/prepared/study.json" \
  --spinenet-run "$MRI_CASE/localization/l002-001" \
  --rsna-run "$MRI_CASE/stenosis/s003-001" \
  --crosscheck-run "$MRI_CASE/geometry/l003-001" \
  --output "$MRI_CASE/fusion/f004-001" \
  --verify-only
```

Для нового запуска убрать `--verify-only` и указать новую папку. Команда выводит путь к HTML в поле `report`.

## Проверки

Формат представления — 1.1. SHA связаны с HTML, Markdown, fusion JSON и evidence JSON. Проверка заново получает факты и картинки из проверенных источников, пересчитывает представления и не пишет файлы. Подмена текста, фактов или PNG не проходит даже после замены их SHA в metadata.

Контрольный отчет: 20 иллюстраций стенозных оценок, 5 кадров дисков, 7 уникальных PNG и 20 фактов. Два запуска дали побайтно одинаковые четыре артефакта. Formal fusion JSON совпал с F002/F003: представление не снимает неподтвержденность и не меняет медицинские исходы. Проверены 161 входной файл и 29 файлов кода. Все 363 теста проходят в RSNA runtime; core — 318 pass / 45 optional skips.

Старые F002/F003 сохранены. Их проверяют соответствующими историческими версиями кода: `0d61c27` и `d0d3129`. Текущая команда проверяет F004.
