# L003 — сопоставление уровней RSNA и SpineNet

На контрольном исследовании все пять native дисковых уровней RSNA согласуются с соседними native позвонками SpineNet на **том же исходном SagT2 кадре**. Это проверка согласованности двух моделей. Абсолютная анатомическая нумерация и межсерийное совмещение остаются неподтвержденными; assessments сохраняют `indeterminate`, `root_impacts=null`.

Входы — неизмененные результаты [L002](localization-run.md) и [S003](rsna-run.md). Нового inference, обучения, чтения CSV разметки или поиска грыж нет. Постоянный результат: `/Users/andrew/Datasets/mri-root-impact-ai/rsna-3139265320/geometry/l003-001`.

## Правило сравнения

1. Проверяются оба completed worker/run report, SHA обязательных артефактов и overlays, восстановление C001 из native, spatial contracts и provenance. Все 60 DICOM повторно читаются с проверкой SHA; записанные геометрические поля сравниваются с исходными заголовками. Для SpineNet сверяются все 15 исходных кадров.
2. Для каждой SagT2 точки RSNA ищется точное совпадение `series_id/image_id/frame_index` среди SpineNet polygons. Порядок массива и `slice_index` не используются как идентичность кадра. В этом исследовании SpineNet и RSNA сортируют срезы в противоположных направлениях; общий срединный кадр совпал, но это не общее правило.
3. Площади и центроиды выпуклых четырехугольников вычисляются формулой shoelace. Проверяются source FOV, pixel/LPS coordinates, IPP/IOP/spacing и размер матрицы. Вырожденные, пересекающиеся или непригодные polygons дают неопределенность.
4. Центроиды независимо от названий позвонков сортируются вдоль patient SI: `-LPS Z`. Находится единственная соседняя пара, строго между центрами которой лежит дисковая точка. Numerical epsilon `1e-6` мм служит только для равенства границ; это не медицинский порог.
5. При уникальной канонической паре L1/L2…L5/S1 ее native labels сравниваются с native уровнем RSNA. Результаты сравнения — `native_agreement`, `native_disagreement` или `indeterminate`. Ни один из них не подтверждает анатомический номер.

При пропущенной или дублированной ожидаемой/наблюдаемой метке, отсутствии точного кадра/полигона, совпадении центров, попадании точки на границу или неканонической соседней паре результат неопределенный. Подстановка ближайшего среза, интерполяция и перенумерация не выполняются.

Дисковые точки находятся позади тел позвонков: попадание внутрь body polygon и близость к евклидовой середине между телами не используются как критерии. Проекция на локальную линию центров и перпендикулярное расстояние записаны только как диагностические величины. Согласие моделей не становится независимой разметкой или оценкой точности.

## Привязка к Axial T2

Для каждого из пяти уровней сохранены соседние SpineNet detection IDs и два side-specific links к существующим входам RSNA. Каждый link содержит 10 использованных axial ROI IDs, включая повторения, пять уникальных source frames и их IOP. Всего это десять links, 100 sampled views и 25 уникальных AxT2 кадров; их индивидуальные геометрии сохраняются.

Сагиттальные polygons не становятся аксиальными crops. Сами ROI, физические footprint corners, сторона/flip и соответствие дисковому сегменту уже проверяются S003; L003 связывает их с результатом сравнения локализаторов. Между SagT2 и AxT2 сохраняется исходное **неподтвержденное identity-LPS допущение** S003: разные FrameOfReferenceUID не исправлялись. L003 не подтверждает регистрацию и не повышает статус старых C001 результатов.

## Артефакты

| Файл | Содержание |
|---|---|
| `crosscheck.json` | Пять сравнений, expected/observed detection IDs, точные source refs, центроиды, причины неопределенности, ссылки на Ax ROI и hashes входных run/artifact файлов |
| `overlays/*.png` | Нативные source pixels с заголовком 48px; общий SagT2 и пять исходных Ax keypoint кадров |
| `overlay.png` | Монтаж этих шести кадров; aspect ratio сохранен |
| `run.json` | Фактическое отсутствие нового inference, параметры, длительность, overlay mapping и SHA результатов |

Зеленые polygons/метки — SpineNet; красные точки/метки — RSNA. На Ax синим отмечен правый source crop, желтым — левый; это существующие перекрывающиеся 60% crops S003. Они не являются сегментацией поражения. На всех панелях явно указано `NATIVE LABELS / UNREVIEWED`.

Наложения просмотрены на геометрическое положение и масштаб. Два свежих прогона сравнения дали идентичные `crosscheck.json`, `overlay.png` и шесть source overlays. Проверки со сдвигом на один диск выявляют расхождение; пропуски и неоднозначность дают неопределенный исход. Данные, координаты и изображения результатов остаются вне Git.

## Повторный запуск

Из корня проекта, с готовыми L002/S003 и существующим RSNA runtime:

```sh
MRI_DATA_ROOT=/Users/andrew/Datasets/mri-root-impact-ai/rsna-3139265320
.venv-rsna/bin/python scripts/compare_localizers.py \
  --study "$MRI_DATA_ROOT/prepared/study.json" \
  --spinenet-run "$MRI_DATA_ROOT/localization/l002-001" \
  --rsna-run "$MRI_DATA_ROOT/stenosis/s003-001" \
  --output "$MRI_DATA_ROOT/geometry/l003-reproduce-001" \
  --allow-missing-modality
```

Output должен быть новым каталогом вне Git и исходных run directories. Исходные данные и результаты не перезаписываются. JSON-сравнение и его тесты используют stdlib; декодирование и PNG требуют существующих pydicom/NumPy/Pillow из `requirements-rsna.txt`. Команда не загружает модели.

Скрипт расположен отдельно от MRI adapters: их исходники не менялись, поэтому строгая проверка code hashes исходного S003 остается действительной. При изменении MRI adapters следует получить новый checked MRI run или использовать соответствующую сохраненным hashes версию; проверка старого source fingerprint не отключается.

Следующий шаг F001 определит анатомические fusion-правила и обработку неизвестных входов. Native согласие L003 само по себе не разрешает вывод о конкретном корешке. Получение trained LDH-комплекта остается D002.
