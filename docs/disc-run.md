# D004 — бинарный признак грыжи SpineNet

Подключен проверенный [D003 grading](spinenet-herniation-audit.md). В [тулзе 0.2.0](tool.md) включается полем `"disc_analysis": "spinenet_binary"` в inference-конфиге. Используются прежние SpineNet source, medical weights и отдельный Python. После локализации отдельный `mri_disc.worker` извлекает IVD volumes и исполняет grading на CPU.

Для каждого из пяти дисков сохраняются native класс 0/1 и logits. Native 1 означает предсказанный моделью признак грыжи, 0 — признак моделью не выявлен; это не подтвержденное наличие/отсутствие патологии. Если IVD не получен, значение остается неизвестным. Размер, сторона, зона и морфология — `null`. Все C001-оценки сохраняют `indeterminate`, отсутствующие — `not_run`.

`disc-analysis/` содержит:

- `disc.json` — native предсказания и точный roster девяти source samples с явным padding;
- `result.json` — C001 `disc_analysis`, native scale `spinenet_v2_herniation_binary`, зависимости от SpineNet localization;
- `inputs/*.f64` — фактические little-endian float64 модельные входы `9×112×224`;
- `images/*.png` — центральный, пятый из девяти, входной срез, без разметки грыжи;
- `run.json` — SHA входов/выходов/кода, runtime, checkpoint, параметры и статус.

Worker проверяет прежнюю локализацию, native геометрию, source/weight SHA, закрепленный runtime и повторно проверяет источники после inference. Единственная совместимость — `numpy.bool = numpy.bool_` внутри worker для устаревшего upstream. Исходный checkout и окружение не меняются; новых весов/пакетов не требуется.

Стандартный Python проверяет run без Torch/NumPy: статус, код, источник/веса, DICOM SHA, native argmax двух logits, отсутствие выдуманных полей, порядок source frames, C001 и все артефакты. PNG побайтно пересчитывается из сохраненного входного volume. Fusion связывает native/worker/C001 артефакты и сохраняет пять исходных дисковых оценок в `raw_disc_evidence`.

Отчет остается в четырех разделах. В дисках показываются бинарный результат и реальный SagT2 crop; в fusion к стенозным находкам добавляется положительный признак грыжи с неизвестной стороной. Если есть только грыжа, вывод — «корешок по этой находке не определён». Стенозная сторона не переносится на грыжу. Формальная policy 0.1.0 не изменена: бинарная грыжа не формирует root candidate, не доказывает причину стеноза; `herniation_context=not_evaluated` в formal fusion относится к правилам воздействия, а native оценка хранится отдельно.

Воспроизводимый полный запуск и проверка — [tool.md](tool.md). Для frozen-сборки добавьте `disc_run` к трем прежним upstream directories. Напрямую fusion принимает `--disc-run`; этот флаг требует все три frozen MRI run и выполняет те же проверки.

Ограничения прежние: нумерация и T2-контраст контрольного примера независимо не подтверждены; side/size/morphology недоступны. Признаки и вероятность клинической радикулопатии не приравниваются. Полный LDH-модуль остается в D002.
