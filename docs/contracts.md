# Контракты данных Stage I, версия 1.0

Контракты реализованы в [mri_root_impact/contracts.py](../mri_root_impact/contracts.py). Они проверяют структуру manifest и результатов отдельных модулей, идентичность входа и ссылки между результатами. Чтение изображений и MRI inference в эту реализацию не входят.

## Запуск

```sh
make contracts
python3 -m mri_root_impact validate --study /external/study.json \
  --result /external/localization.json --result /external/stenosis.json
```

Первый вызов проверяет [синтетические примеры](../harness/fixtures/contracts/). Второй показывает работу с внешними файлами. Все результаты, на которые есть upstream-ссылки, передаются через повторяемый `--result`; порядок аргументов не имеет значения. Без результатов проверяется только manifest.

Успех: JSON в stdout и код 0. Ошибка данных, чтения или ссылок: JSON в stderr и код 2. CLI отклоняет повторяющиеся ключи JSON, NaN и Infinity. `make check` автоматически запускает тесты и проверяет bundle примеров. Вызов валидатора не изменяет входные файлы.

## Исследование: study_manifest

Обязательные поля: `schema_version`, `kind`, `study_id`, `synthetic`, `series`, `limitations`.

- `schema_version` — строка `1.0`, `kind` — `study_manifest`.
- `study_id`, `series_id`, `image_id` — устойчивые идентификаторы из букв ASCII, цифр, точки, дефиса и подчеркивания. Это внутренние ссылки проекта; соответствие DICOM UID не требуется. Идентификаторы сами по себе не гарантируют обезличивание.
- `synthetic` — явный boolean. В Git допустимы только синтетические примеры без извлеченных данных пациентов.
- Каждый элемент `series` содержит `series_id`, `sequence`, непустой список `images`. Значения sequence: `sagittal_t1`, `sagittal_t2`, `axial_t2`, `other`, `unknown`. Метка не подтверждает фактическое содержимое серии.
- Изображение содержит `image_id`, абсолютный локальный `path`, положительный целый `frame_count` и `sha256` — контрольную сумму файла либо явный `null`, если она еще не рассчитана. Формат контейнера и чтение кадров определит адаптер.
- `limitations` — список известных ограничений. Отсутствующая серия не добавляется как пустой фиктивный объект. Если `series=[]`, необходимо указать причину в `limitations`.

Идентификаторы серий уникальны внутри исследования; идентификаторы изображений — во всем исследовании. Валидатор не открывает пути и не проверяет доступность файлов, реальный frame count, качество изображений или полноту протокола.

## Результат модуля: module_result

Один файл описывает один компонент: `localization`, `disc_analysis`, `foraminal_stenosis` или `subarticular_stenosis`. Каждый результат содержит:

- `schema_version=1.0`, `kind=module_result`, уникальный в bundle `result_id`;
- `study_id`, `synthetic`, `study_digest`;
- `component`, `producer` и непустой список `assessments`.

`study_digest` вычисляется функцией `manifest_digest`: SHA-256 от JSON в UTF-8 с сортировкой ключей объектов, `ensure_ascii=False`, разделителями `,` и `:`, без NaN. Порядок массивов сохраняется. Это привязка к точной версии manifest, включая пути; она не подтверждает байты изображений, особенно при `image.sha256=null`.

`producer` содержит `name`, `version`, `method` (`synthetic`, `manual`, `model`) и `model`. Для выполненной модельной оценки `model` содержит `name`, `version`, `weights_sha256`. Если модель отсутствует, `method=model` и `model=null` разрешены только для результатов, где все оценки имеют статус `not_run` или `error`. Для других методов `model=null`; метод `synthetic` разрешен только для синтетического исследования.

## Оценка конкретной области

Каждый assessment содержит `assessment_id`, `target`, `status`, `reason`, `observation`, `image_refs`, `upstream_refs`. Идентификатор assessment уникален внутри результата.

`target` всегда явно задает:

| Поле | Значения |
| --- | --- |
| `level` | L1…L5, S1; L1-L2…L5-S1; `unknown` |
| `side` | `left`, `right`, `midline`, `bilateral`, `not_applicable`, `unknown` |
| `zone` | `vertebral_body`, `disc`, `central`, `subarticular`, `foraminal`, `extraforaminal`, `unknown` |

Локализация использует зоны `vertebral_body` или `disc` и сторону `not_applicable`; неустановленные поля обозначаются `unknown`. Остальные компоненты относятся к дисковым уровням. Фораминальный и субартикулярный стеноз имеют соответствующую зону и отдельную оценку каждой стороны (`left`/`right` либо `unknown`). Валидатор проверяет эти ограничения, но не определяет анатомию по изображениям.

| `status` | Требования и смысл |
| --- | --- |
| `assessed` | Все поля target установлены; есть observation и ссылки на изображения; `reason=null`. Получена оценка указанной области в заявленной шкале. |
| `indeterminate` | Непустая причина. Допускается исходный observation с изображениями, но его анатомическая привязка или интерпретация остается неопределенной. |
| `not_run` | Непустая причина, `observation=null`. Например, отсутствуют нужная серия или модель. |
| `error` | Непустая причина, `observation=null`. Ошибка не считается отрицательной находкой. |

`observation` содержит исходные `label`, `scale_id` и `measurements`. Шкала обязательна для любой метки. Измерение содержит уникальное имя, конечное числовое значение и явную единицу; при отсутствии измерений используется `[]`. Конвертация единиц, семантика классов и пороги здесь не задаются.

`assessed` не означает «патологии нет». Метка `normal_mild` сохраняется как исходный класс, без преобразования в отсутствие стеноза. Синтетические примеры используют вымышленную шкалу `fixture:stenosis-grade:v1`; соответствие реальным классам моделей предстоит проверить. Отсутствие assessment или целого результата означает отсутствие оценки, а не норму. Полнота охвата уровней и сторон из наличия файла не выводится.

## Источники и зависимости

`image_refs` содержит `series_id`, `image_id`, `frame_index`. Кадр должен существовать в объявленном диапазоне `0 <= frame_index < frame_count`. Это **индекс проекта с нуля**, а не DICOM Frame Number. Адаптер обязан явно преобразовать нумерацию источника. Ссылки на неуказанную серию/изображение и дубли отклоняются.

`upstream_refs` содержит пары `result_id`, `assessment_id`, например ссылку классификатора на использованную локализацию. Ссылка разрешается только в другом переданном результате того же исследования. Циклы и отсутствующие источники отклоняются. `assessed` не может зависеть от неразрешенной upstream-оценки; результат с сохраненным исходным классом тогда остается `indeterminate`.

Если `assessed` ссылается на локализацию дискового уровня, его дисковый уровень должен совпадать с источником. Соотношение позвонков и дисков, соответствие native label нормализованной анатомии и пригодность последовательности для конкретной модели здесь не проверяются.

## Что появится следующим

L001 уточнил native API выбранного SpineNet: метки позвонков и polygons по индексам входных срезов, без voxel masks. В L002 нужен отдельный версионированный контракт геометрии с обратной привязкой к исходным DICOM; текущая строгая schema 1.0 произвольные ROI-поля не принимает. Требования описаны в [аудите локализатора](localizer-audit.md). Контракт итогового вывода о корешке, правила и пороги относятся к F001. Текущий `module_result` не является итоговым заключением о корешке или клинической радикулопатии.

Версия 1.0 использует строгий набор полей: опечатки и неизвестные поля отклоняются. Изменения формата требуют явного обновления версии и примеров. Файлы в `harness/fixtures/contracts/` содержат только вымышленные данные и несуществующие пути; `assessed` в них иллюстрирует формат, а не состоявшийся запуск модели.
