# D003 — SpineNet для признака грыжи

Проверено 21 октября 2026. **SpineNet v2 можно использовать как исследовательский baseline наличия грыжи на дисковом уровне.** Это частичное покрытие дискового модуля; размера, стороны и морфологии грыжи он не возвращает.

## Возможности

| Нужный результат | Встроенный grading SpineNet v2 |
|---|---|
| Бинарный признак грыжи | Да, `Herniation`, классы 0/1 |
| Дисковый уровень | Да, через детекцию соседних тел позвонков; нумерация требует проверки |
| Размер в мм | Нет |
| Сторона и зона грыжи | Нет |
| Протрузия / экструзия / секвестрация | Нет |
| Маска или контур грыжи | Нет; IVD crop — входная область, не сегментация патологии |
| Воздействие на конкретный корешок | Не определяется этой бинарной головой |

Вход grading — **сагиттальная T2 поясничного отдела**, а не Axial T2. [Официальная документация](https://spinenet.readthedocs.io/en/latest/running-spinenet.html#grading-ivds) явно описывает Disc Herniation (Binary). В [технической статье, таблица 3](https://arxiv.org/html/2205.01683#S5.T3) для грыжи указана balanced accuracy 80.4% на отложенной части Genodisc. Это результат авторов на их данных, не точность на нашем RSNA-примере.

## Проверенный код и веса

Использован уже закрепленный commit `5e96ac54b1c1845a37d12e40bfd16f647d40acd8`. `SpineNet.grade_ivds()` вызывает `classify_ivd_v2_resnet`; один из 11 выходов — бинарный `Herniation`. Реальная голова `fc_hrn` содержит два выхода. В `gt_formatting.py` положительные исходные метки грыжи сводятся к 1; отрицательная метка — 0. `format_gradings()` разворачивает уровни и предсказания вместе.

Нужный medical checkpoint уже есть: `grading/ckpt1.pt`, SHA-256 `b7259f0a32d438d30e58db0f36db0b401ae5e36cb58d3eddb650cd7a141778fb`. Загрузка выполняется строго по сохраненному inventory; проверены исходный Git tree и все четыре прежних checkpoint. Дополнительных весов и пакетов не скачивали.

[Лицензия](https://github.com/rwindsor1/SpineNet/blob/5e96ac54b1c1845a37d12e40bfd16f647d40acd8/LICENCE.md) ограничивает код, pretrained weights и outputs некоммерческими исследованиями. Для продукта это не дает коммерческого разрешения.

## Пробный запуск

Проверен контрольный RSNA 3139265320 с сохраненными и повторно проверенными L002 polygons. Повторной локализации нет; загружена настоящая grading-сеть на CPU. Получены шесть IVD crops T12–L1…L5–S1 размером `9×112×224` и шесть бинарных предсказаний. Пять требуемых уровней присутствуют. Два запуска `grade_ivds()` совпали; дополнительный прямой проход подтвердил привязку каждого DataFrame-уровня к соответствующему crop. Три grading-прохода заняли 7.50 с; вся проверка с загрузкой и SHA — 19.80 с.

Native class 1 получен на L3–L4, на остальных уровнях — 0. Это **непроверенные предсказания модели**, без заключения о наличии/отсутствии грыжи у пациента. Нумерация не подтверждена; исходная серия описана как T2/STIR-like, обычный T2-контраст независимо не подтвержден. Пример доказывает исполнимость, но не качество классификации.

Обнаружен технический дефект upstream: извлечение IVD использует удаленный `np.bool`. Неизмененный код падает в нашем NumPy 1.26.4. Пробный процесс использует явную совместимость `np.bool = np.bool_`; исходный checkout и установленное окружение не менялись. Перенос этой совместимости в адаптер требует отдельной реализации и проверки. Существующий `detect_vb` этой ветки кода не вызывал.

Все исходные DICOM, manifest, L002 artifacts, upstream code и веса после запуска сверены по SHA. Проектный pipeline, fusion policy и последний отчет не изменены.

## Решение

Следующий шаг — отдельный адаптер бинарного признака с проверенным входом, IVD-иллюстрациями, native классом и неопределенностью. Отображать можно «модель предсказывает признак грыжи на уровне …»; сторону, размер и тип оставлять неизвестными. Бинарная грыжа не становится доказательством причины стеноза или воздействия на корешок. D002 по полному LDH-комплекту и морфологии остается отдельной задачей. Текущий `main` по-прежнему запускает Stage I без анализа грыж.
