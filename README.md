# MRI Root Impact AI

Отдельный локальный репозиторий Stage I: оценка признаков потенциального воздействия на нервные корешки по МРТ поясничного отдела. Границы проекта зафиксированы в [scope](docs/stage-1-scope.md).

Сейчас реализованы [контракты исследований и результатов модулей](docs/contracts.md), их JSON-валидатор, подготовка и проверка [контрольного RSNA-исследования](docs/control-study.md), рабочий harness, [локализация SpineNet](docs/localization-run.md), [запуск моделей стенозов RSNA с автоматическими ROI](docs/rsna-run.md) и [исполняемый анатомический fusion](docs/fusion-run.md). Анализ грыж остается отдельной незавершенной веткой.

L001–L003 завершены: [SpineNet выбран для исследовательской локализации](docs/localizer-audit.md), запущен на CPU; сохранены polygons и [привязка к исходным DICOM](docs/spatial-contract.md). [Сопоставление с RSNA](docs/level-crosscheck.md) показывает согласие всех пяти native дисковых уровней на том же SagT2 кадре. Независимое анатомическое подтверждение номеров еще не выполнено.

D001 завершен: [аудит LDH-DL-MODEL](docs/ldh-audit.md) выявил отсутствие подтвержденных обученных lumbar-весов и измерительного конвейера в проверенном публичном комплекте. Расширенный публичный поиск D002 пока не закрыл этот пробел; подход остается кандидатом для адаптации.

S001–S003 завершены: [обученные RSNA-модели найдены](docs/rsna-audit.md), [три checkpoint проверены в отдельном CPU-окружении](docs/rsna-assets.md), получены 20 native оценок на контрольном МРТ. Серии имеют разные FrameOfReferenceUID: реальный исследовательский запуск использует явный флаг неподтвержденного совмещения; по умолчанию grades блокируются. Все результаты остаются `indeterminate`, анатомическая нумерация и регистрация не подтверждены.

F001/F002 закрепили [спецификацию анатомического fusion](docs/fusion-spec.md), исследовательский порог Severe-only и выполнили 34 синтетических сценария. На сохраненных MRI-входах fusion дает 20 неопределенных ветвей и 0 именованных кандидатов; классы стеноза и причины неопределенности сохранены. Согласие моделей не снимает review-gates; Normal/Mild не означает свободный корешок. [Отчет воспроизводится без нового MRI inference](docs/fusion-run.md). Следующий E001 задаст протокол независимой технической оценки.

Каждый успешный запуск fusion автоматически создает [краткий отчет для врача](docs/physician-report.md): четыре раздела — диски, фораминальный стеноз, субартикулярный стеноз, Fusion. В таблицах указаны уровень, результат и картинка; в Fusion — строки «находки ⇒ вывод». Подробности сохранены в JSON. LDH-детектор пока не подключен; грыжи не считаются отсутствующими.

## Быстрый запуск

Тулза [MRI Report Tool 0.1.0](docs/tool.md): подготовленный набор МРТ → краткий отчет F005. Полный запуск выполняет проверку DICOM, SpineNet, RSNA, сопоставление и fusion одной командой:

```sh
python3 scripts/run_mri.py --study /path/to/prepared/study.json \
  --config /path/to/config/local-models.json --output /path/to/runs/new-run
```

Результат — `new-run/fusion/report.html`; готовые стадии можно использовать в режиме `frozen`. Команда с `--verify-only` проверяет сохраненный запуск без моделей и записи. Конфиги и рабочий локальный пример — в [инструкции](docs/tool.md). Модели и их отдельные Python-окружения должны быть подготовлены заранее.

## Harness

Нужны Python 3.9+ и Git. Установка пакетов и доступ к сети не требуются.

```sh
python3 scripts/harness.py doctor
python3 scripts/harness.py status
python3 scripts/harness.py check
python3 scripts/harness.py smoke
make contracts
```

При наличии Make доступны те же команды: `make doctor`, `make status`, `make check`, `make smoke`.

`doctor` проверяет окружение; `status` показывает очередь; `check` запускает проверки harness; `smoke` проверяет синтетический manifest и запись/чтение артефакта. Успешный smoke подтверждает работу harness. В артефакте явно указаны `kind=harness_smoke`, `synthetic=true`, `inference_performed=false`, `root_impacts=null`; все четыре стадии имеют статус `not_configured`.

`make contracts` проверяет синтетический bundle с локализацией, оценкой в исходной шкале, неопределенным результатом и пропущенным запуском. Эта проверка входит в `check`. Для своих файлов: `python3 -m mri_root_impact validate --study /external/study.json --result /external/module-result.json`. Изображения не открываются, входные файлы не изменяются.

Реальные входы проверяет отдельная команда `python -m mri_root_impact preflight --study /external/study.json --output /external/preflight.json`: она читает DICOM, сверяет SHA-256 и декодирует кадры. Для нее нужны дополнительные зависимости из `requirements-data.txt`; базовые проверки harness по-прежнему работают без них. Команды получения, подготовки и повторного прогона контрольного примера находятся в [инструкции](docs/control-study.md).

1. Выбрать готовую задачу из [очереди](harness/tasks.json) и выполнить один проверяемый шаг.

3. Синхронно обновить статус задачи и её зависимости.
